# Orbit Wrapper Template

This is a local wrapper template for projects that combine:

- documents and assets that should sync through iCloud;
- one or more independent Git repositories; and
- optional local-only orchestration.

The iCloud project is the human-facing starting point. A canonical Git
repository can be attached later, and this wrapper is optional local control
plane. The wrapper never owns source files and never puts Git metadata in
iCloud.

## Layout

```text
project-orbit/
├── bin/
│   ├── doctor
│   └── lib.sh
├── config/
│   ├── orbit.conf.example
│   └── orbit.conf               # local-only, generated by Orbit
├── local/
│   └── repo/                       # local-only symlink directory, optional
│       ├── repository-a -> <repository-a>
│       └── repository-b -> <repository-b>
├── remote/
│   └── iCloud -> <iCloud project> # local-only symlink
├── .gitignore
└── README.md
```

The canonical repository lives separately under the consumer's configured
`repository_root`.
The `local/repo/<repository-name>` symlinks are only a local convenience view,
while `remote/iCloud` exposes the synced document project. Both boundaries and
`config/orbit.conf` are intentionally ignored by the wrapper repository.

`config/orbit.conf` is a small plain-text configuration file. It stores the
project name, iCloud project path, and one named repository section per
attachment:

```ini
[repository "product"]
path = /path/to/canonical/product
```

The repository section name is the local symlink name.
Orbit derives the
two local symlink paths from the wrapper root, so they do not become stale
configuration values.

## Lifecycle

Orbit creates and initializes this wrapper. From the wrapper root, use the
main CLI for lifecycle operations:

```bash
orbit doctor
orbit open --dry-run
orbit attach "/path/to/canonical/repository-a" "/path/to/canonical/repository-b"
```

These commands also work from nested directories because Orbit discovers the
wrapper by walking upward. The wrapper contains only the local control-plane
scripts and configuration; it does not provide a second public CLI.

## Storage contract

The wrapper repository owns its scripts and configuration templates. The
canonical repository owns source code. iCloud owns notes,
references, assets, exports, and other sync-worthy documents. Keep secrets,
credentials, `.git` directories, dependencies, and build output out of the
iCloud project.

`orbit open --dry-run` shows the three intended destinations without opening
any applications. Use `orbit open --launch` when the paths look correct.
