# Studio Context Template

This is a private context template for studios that combine:

- documents and assets that should sync through iCloud;
- one or more independent Git repositories; and
- optional private, local-only orchestration.

The iCloud studio is the human-facing starting point. Git repositories are
attached later, and this local context is an optional control plane. The
context never owns company source files and never puts Git metadata in iCloud.

## Layout

```text
studio-context/
├── bin/
│   ├── bootstrap
│   ├── doctor
│   ├── lib.sh
│   └── open-project
├── config/
│   ├── project.env.example
│   └── project.env              # local-only, generated by bootstrap
├── local/
│   └── repo -> ~/Repositories/... # local-only symlink, optional
├── remote/
│   └── iCloud -> <iCloud project> # local-only symlink
├── .gitignore
└── README.md
```

The canonical company repository lives separately under `~/Repositories`.
The `local/repo` symlink is only a local convenience view, while
`remote/iCloud` exposes the synced document project. Both symlinks and
`config/project.env` are intentionally ignored by the wrapper repository.

## First run

From the wrapper root:

```bash
./bin/bootstrap
./bin/doctor
```

This creates the iCloud-side studio folders first. It does not require a Git
repository to exist yet.

To exercise the complete flow with a safe fixture, use:

```bash
./bin/bootstrap --demo
./bin/doctor
```

`--demo` creates a tiny independent repository outside the context, next to it
under the local repositories area. It never creates a nested company repo.

For a real checkout, either attach an existing repository directly:

```bash
./bin/bootstrap --attach-repo "$HOME/Repositories/Acme/product"
./bin/doctor
```

or edit `config/project.env` and set `COMPANY_REPO` to the existing repository
path, then run:

```bash
./bin/bootstrap
./bin/doctor
```

Bootstrap refuses to overwrite an existing non-symlink at either boundary
boundary. Doctor returns a non-zero exit status if any configured ownership or
hygiene check fails. An unattached company repository is reported as optional,
not as an error.

## Storage contract

The context repository owns its scripts and configuration templates. The
canonical company repository owns its source code. iCloud owns notes,
references, assets, exports, and other sync-worthy documents. Keep secrets,
credentials, `.git` directories, dependencies, and build output out of the
iCloud project.

`open-project --dry-run` shows the three intended destinations without opening
any applications. Use `open-project --launch` when the paths look correct.
